# Changelog

## 0.3.0 — M12: JavaScript assigned methods, C# ranking, fewer ambiguous call edges (2026-10-01)

**Upgrade:** the parser artifact (6), FTS builder (2) and edge resolver (3) versions changed; the first `token-context index --all` after upgrading re-parses and re-indexes every repository. Python results are unchanged byte for byte (`tc-pinned` loc/edge gate and `rich` bench: 0 differences).

- **JS (M12.1)** — methods assigned through `X.prototype.m = function…`, `X.prototype = {…}`, `Object.defineProperty(X.prototype, …)`, `X.m = …`, `this.m = …` in constructor functions, `exports.m`/`module.exports.m` and module-level object literals are indexed as symbols (`docs/SYMBOL_NAMING.md`).
- **C# (M12.2)** — implementation ranking over interface/abstract declarations, doc comments attached to the member instead of the container (`FTS_BUILDER_VERSION` 2) and interface doc inheritance.
- **Call edges (M12.3)** — E1 implicit `this`, E2 overload resolution by arity/group, E3 C# namespaces, E4 local variable types, E5 fields without `this.`, E6 instantiation edges (`new X`, `new X()`), E7 missing C# call forms, E8 CommonJS module bindings, E10 TS property-signature field types (`RESOLVER_VERSION` 3).
- **Fix after review of the M12 run** — the per-file wall-clock circuit breaker in the edge resolver made edge counts depend on machine load (the same repository indexed alone or with `--all` gave different graphs). It is replaced by a deterministic work budget (`FILE_EDGE_WORK_BUDGET`); `RESOLVER_VERSION` joins the parser fingerprint and the manifest, so a resolver change re-indexes (it did not before); the I1 test (incremental equals full) now also holds across a version bump.
- **Harness** — Rule 17 guard hardened (`evals/guard.py`: held-out runs need tag `m12-freeze` and an empty diff on every protected path, or a baseline tree byte-identical to `m12-base`; real-git tests in `tests/test_guard.py`); `evals/edge_gold_eval.py`, `evals/sample_call_sites.py`; C3 v2 (`evals/run_c3*.py`, `c3_adapters.py`, `c3_grade.py`, `c3_locate_suite.py`): watchdog timeout, turn limit, case-preserving path grading, explicit dev/held-out suite roles; lint scripts honour `gold_pending_indexer`.
- **Evidence** — dev before/after, held-out old/new, C3 with Claude Sonnet 5.5: `docs/BENCHMARK.md` (M12), `evals/out/m12/`. Four dev edge-gold labels for hono were wrong and were corrected (`evals/out/m12/edge_gold_hono_corrections.md`).

## Unreleased — M7: incremental, parallel, commit-aware index — schema 2.4 (2026-09-29, branch `feat/m7-incremental-index`)

- **Schema 2.4 (`INDEX_SCHEMA_VERSION = "2.4"`)** — new table `file_parse_artifacts(path, sha256, parser_version, language, calls_json, inheritance_json, imports_json, warnings_json, facts_json)`: the parse result of every file, keyed by content hash, is stored in the snapshot so the next run can skip parsing. **The first `index` after upgrading re-parses every file** (snapshots 2.1–2.3 have no artifacts; they are never used as a base and get a full rebuild). Older snapshots still open for reading and `get_index_status` warns to re-index.
- **`PARSER_ARTIFACT_VERSION = 1` (`parse/treesitter.py`)** — bump it whenever the parser output for the same bytes can change (extraction rules, `CallRecord`/`ImportRecord` layout). `tests/test_parser_artifact_version.py` pins a golden hash of the parser source and the record layout and fails until the version is bumped. The tree-sitter package versions are also stored as `parser_fingerprint`; a different fingerprint forces a full re-parse.
- **Incremental build (`index/runner.py`)** — files are classified by `(size, mtime_ns)` against the active snapshot: unchanged files are neither read nor hashed nor parsed; touched files with an identical hash are hashed but not parsed; only changed/new files go through `parse_source`. Deleted files disappear from every table. `--verify-hashes` reads and hashes every file, `--full` ignores the active snapshot. **Known limitation**: a same-size edit that keeps the mtime and is older than the previous scan start (racy window 2 s) is not detected without `--verify-hashes`.
- **Parallel parse** — `ProcessPoolExecutor` with the `spawn` start method, `--workers N` / `TOKEN_CONTEXT_INDEX_WORKERS` (default `max(1, min(8, CPUs-1))`). Deviation from the plan, measured: spawn start-up costs ~0.8 s on the 2-core dev VM, so the pool is used only for ≥32 candidate files **and** ≥1 MB of source (`PARSE_POOL_MIN_FILES/BYTES`); smaller batches, and any pool failure (`BrokenProcessPool`, pickling, OS errors), fall back to the sequential path with identical output. SIGTERM/SIGBREAK/Ctrl-C terminate and reap the workers (test: no orphans).
- **Scoped edge resolution** — edges of unchanged files are reused unless the class hierarchy / stubs fingerprint (`edge_context_sha256`) changed or the file mentions a symbol whose (qualified name, kind, signature) changed; ids of re-parsed files are remapped by `(qualified_name, kind)`. Any inconsistency falls back to re-resolving the file. Edge order is identical to a full build. `lexical_edges` keeps its 30 ms per-file circuit breaker in normal runs (the equivalence tool disables it so timing cannot change results).
- **Write path** — no `VACUUM`; the legacy `<repo>.sqlite` copy is a hard link (copy fallback); when only a few files changed the new snapshot is a copy of the previous one with the changed files' FTS rows replaced (`write_mode = "delta"`, capped at 25 generations or 25 % free pages, otherwise `"rewrite"`).
- **Performance work without behaviour change** — roles in O(n) (children index, lazy source reads), own-body via bisect, ranking loop hoisting (bit-identical), module-candidate cache. Byte-identical index vs. the pre-M7 code on `tc-pinned` (except the new table / schema metadata).
- **Cheap `get_index_status`** — reads aggregates from the manifest (`symbols_with_roles`, `role_counts`, `edge_precision`, `import_count`, `importer_count`) instead of scanning tables (older snapshots fall back to the scan). New fields `commit_sha` (manifest, from `git rev-parse HEAD` with a 2 s timeout, `null` outside git) and `head_changed_since_index` (`true/false/null`, 5 s cache).
- **CLI** — `index --repo-id X | --all` (mutually exclusive; `--all` prints a JSON summary `{repositories, indexed, failed}` and exits 1 when any repository failed), `--progress-format ndjson` (one JSON object per line on stdout, ≤10/s, final `{"stage":"done","manifest":...}`; logs stay on stderr; `--all` lines carry `repo_id` and end with `all_done`), `--workers`, `--verify-hashes`, `--full`, `--watch [--debounce S] [--poll-interval S]` (re-index after the tree has been quiet for the debounce; uses `watchdog` when installed — optional extra `watch` — otherwise polls; ignores `.gitignore`d and vendored paths).
- **Evidence** — `evals/index_equivalence.py` (invariant I1: incremental == from-scratch after 5 chained edits — body edit, rename with cross-file caller, add, delete, import change — with exact `parse_source` counts 1/2/1/0/1; passes on `tc-pinned` and `synthetic-1k`), `evals/index_bench.py`, `evals/out/m7/`. Regression gate (loc A1final/A2 held-out @8192 + `edge_eval`, `tc-pinned` re-indexed): identical to baseline.
- **Measured on the 2-core dev VM (median of 3)**: `tc-pinned` (137 code files) full 1.99 s → 2.09 s (parse-bound, no gain on 2 cores), no-op 2.26 s → 0.42 s, one file 2.22 s → 0.45 s; `synthetic-1k` (1050 files) full 8.28 s → 5.23 s (−37 %), no-op 0.77 s (15 % of full), one file 0.81 s; tracemalloc peak 44.9 → 36.4 MB (full); tree RSS 62–66 → ~70 MB full / 56 MB no-op; `get_index_status` p50 97 ms → 3.6 ms. Soft KPIs not met on this VM: `tc-pinned` full speed-up, full-index −40 % on synthetic-1k (−37 %), tree RSS −30 %; see `docs/reports/M6_M10_REPORT.vi.md`.

## Unreleased — M6 Session 2: context packet in `inspect_symbol(view="full")` (2026-09-29, branch `feat/m6s2-packet`)

- **Contract change (D9, approved by the owner)** — `inspect_symbol(view="full")` now returns a context packet. `minimal` and `normal` are unchanged (guarded by 40 JSON snapshots captured before any packet code, `tests/test_inspect_symbol_snapshots.py`). `full` returns:
  - `data.symbol` (same fields as `normal`, no `content`), `data.packet`, `data.relationship_count` (filtered 1-hop relations, callee + caller, de-duplicated) and `data.relationships_filtered` (E14 meaning: edges excluded by the quality filter).
  - `data.content` and `data.relationships` are **removed** from `full` (both live inside the packet; keeping them would count every token twice).
  - `data.packet = {target, callees, callers, more, context, files, used_tokens, omitted}`:
    - `target`: `{symbol_id (ref8), span, content, truncated_lines}`. A function/method body is complete when it fits; otherwise the kept lines are prefixed `"<line>: "`, always include the signature, the first docstring line and every line that calls a retained callee, and `truncated_lines` lists the omitted ranges. A class target is a skeleton (header + method signatures), not a body.
    - `callees` / `callers`: `[ref8, "path:line", "<signature>", confidence]`; callees ordered by first call in the target body, callers regular code before `evals/` before `tests/` (then global rank, path, line), at most K per response. A constructor call resolves to the class, and the row carries the `__init__` signature (header when there is none).
    - `more`: every remaining 1-hop relation as `[ref8, "path:line", "f name", "callee|caller|test"]`. `context`: `imports` used by the target and `class_methods` (sibling signatures). `files`: `path -> sha256[:12]` written once. `omitted`: rows shed for budget (`callees`, `callers`, `more`, `class_methods`, `imports`).
    - Edge filter shared by the packet and every metric: callee edges satisfy `edge_is_traversable(e, 0.6)`, caller edges `edge_is_traversable(e, 0.5)`.
    - `ref8` (first 8 hex of sha256(symbol_id)) is accepted as `symbol_id` by `get_symbol_context` and `get_impact_slice` (tested).
    - A neighbour file that changed after indexing keeps its row and ref; the signature is `null` and `stale_content_unavailable` is added to `warnings`.
- **Budget contract** — the response is built with a fixed-point loop: `_payload_tokens(response) <= _effective_budget(budget_tokens)` on the *whole* response (envelope included), `budget.estimated_tokens` is the measured number (no more `min(budget, …)` clamp), and a too-large response sheds `more -> context -> callers -> callees -> target lines`. Tested at 1.024 / 2.048 / 4.096 for short and >300-line targets, also through `server._result` in `structured` and `text` output modes.
- **Algorithm (`retrieve/packet.py`, `retrieve/packet_inputs.py`)**: `RetrievalService.packet_inputs` gathers the material once per request (no budget); `build_context_packet` is a pure, deterministic function (same inputs -> same bytes). Pass 1 fills `target -> callees -> callers -> more -> context` by share with carry-over of unused bytes; pass 2 gives the remainder to sections that were still cut, in the same order.
- **Frozen constants (tuned on the 8 dev tasks only, 24-config grid in `evals/out/m6/packet_tuning_dev_grid.json`, commit `freeze packet constants`)**: shares `target 0.30 / callees 0.25 / callers 0.25 / more 0.08 / context 0.12`, `CALLERS_K = 15` (initial values were 0.45 / 0.20 / 0.12 / 0.10 / 0.13 and K = 5).
