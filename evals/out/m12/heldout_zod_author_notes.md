## Doubtful tasks (reviewer, please look first)
- t20 (b): `classic/compat.ts::setErrorMap`. `v3/errors.ts` has another `setErrorMap` (module-level override). The query only fits the classic shim (forwards into `config({customError})`), but a reader who only sees "set the global message callback" could accept both.
- t14 (b): `floatSafeRemainder` also exists in `v3/types.ts` with different logic (decimal-count scaling). The query's "four machine epsilons scaled by the quotient" only matches the v4 core function.
- t26 (c): `generateDiscriminatedUnionCheck` does not call `discriminatorMap`; it re-derives the claimed values itself. Both are legitimately "the same feature in two parsers", but the link is thematic, not a call edge.
- t25, t29, t30 (c): gold is a set of cooperating pieces (helper + the compile site that hoists/uses it). t30's `partPattern`/`leafPattern` build the regex in `$ZodTemplateLiteral`'s init; `templateLiteralProcessor` and `generateTemplateLiteralCheck` only read the finished `_zod.pattern`. The query is worded as a data-flow ("folded into one regex that ... both reuse"), which is true, but a reviewer may prefer a smaller gold set.
- t28 (c): `getTupleOptStart` exists in both `core/schemas.ts` and `core/compile.ts`; both are in gold (query spans runtime and compiled parsers).
- t02 (a): `locales/be.ts` has a near-identical Belarusian helper; the query says Russian, so only `ru.ts` fits.
- p05: target `classic/in-out.ts::input` shares its name with a type alias `input` in the same file; verify resolves it to the function (28-36).
